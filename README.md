# 养老机器人共享结算台

本仓库记录该项目已确认的领域对象、事件名称和基础校验方式，并提供一套可按实际使用形成资金责任链的结算引擎，便于不同系统交换一致的数据。

## 资料范围

- `contracts/domain.schema.json`：领域事件信封、聚合类型与事件名称。
- `data/sample.json`：一条用于本地联调的中文样例。
- `src/validator.js`：事件信封的最小校验（必填字段、版本号、类型枚举）。
- `src/timeutil.js`、`src/split.js`：账期/区间计算与按优先级瀑布拆分的纯函数。
- `src/engine.js`：结算引擎，覆盖资格、租赁、计量、停机换机、拆分、确认、封账、争议、退款与视图。
- `src/domain.ts`：上述领域对象的类型定义。
- `tests/`：验证样例符合基础约定，并覆盖结算引擎的主要场景。

## 结算规则

- 资格决定、租赁时段、服务包、设备计量、停机与替换关系分别版本化；记录一经接收，标识、发生时间与版本不得原地改写，更正使用新的后继记录。
- 每段费用按服务发生时的资格与服务包规则拆分，先由机构财务确认，再在封账时入账。
- 资助方按优先级承担费用，任何一方不得突破其月度额度；全部额度耗尽后的余额进入未覆盖桶，等待家庭另行处理。
- 争议只冻结对应分录，同周期其余分录照常确认与封账；老人已获得的服务事实（计量记录）不回滚。
- 换机保留原租赁连续性（同一租约追加设备分配链）；同一设备的重叠计量与并发占用一律拒绝。
- 迟到回执只调整未封账周期；已封账周期以追加差额分录并注明原因的方式处理，原账目不改写。
- 引擎状态完全由事件日志重放得到；服务恢复后调用 `resumePending()` 继续未完成的封账和退款，重复调用幂等。

## 视图与权限

- 家庭（`family`）：只能查看本户明细，包括每条费用由各资助方承担的拆分。
- 资助方（`funder`）：只能查看自身承担的汇总，不含服务明细与其他资助方信息。
- 审计（`audit`）：可查看每一小时由谁支付，以及各资助方剩余额度如何变化。
- 机构财务（`finance`）：确认分录、执行封账。

个人、机构及商业敏感信息仅向履行职责所需的调用方开放。

## 本地检查

```bash
node --test
```

## 测试与构建

测试命令：

```bash
npm test
```

编译或构建命令：

```bash
npm run build
```

这些命令可在单个 Linux 应用容器内执行，不需要另行启动外部服务。
